# TransRealm 数据安全：迁移 / 备份 / 恢复 / 清理

本文档说明 V1.0 候选 0.1.0 在 Windows 11 上的数据存储、迁移、备份、恢复与清理行为，并给出安全建议。使用说明见 [`user-guide.md`](user-guide.md)。

## 1. 数据存储

- 单个 SQLite 数据库文件：**`%USERPROFILE%\.transrealm\project.sqlite`**。
- 其中包含：项目、源文档与段、连接（仅凭据引用，无密钥正文）、Profile、Glossary、翻译 Run/Attempt/Revision、迁移历史。
- 程序目录只读不影响运行；应用数据始终写入用户可写目录。

## 2. 迁移

- 版本升级时，打开项目会自动执行尚未应用的数据库迁移（当前共 12 个迁移）。
- **迁移前会自动创建一致性备份**：备份文件位于数据目录，命名形如
  `project.pre-upgrade-<UTC 时间戳>.db.bak`（同目录、备份前不删除任何既有文件）。
- 迁移失败不会破坏原库：失败时保留原库与备份，应用可继续以旧数据启动。
- 迁移只追加新编号迁移，不修改历史迁移文件。

## 3. 备份

- **自动备份**：每次升级迁移前产生 `project.pre-upgrade-*.db.bak`。它是升级前的一致性快照，可用于回滚（见 §4）。
- **建议的手动备份**：由于数据是单个 SQLite 文件，在应用**完全关闭**后复制 `%USERPROFILE%\.transrealm\project.sqlite` 即为整库备份。请勿在应用运行时直接复制活库文件（存在写竞争）；先正常关闭应用再复制。
- **跨机器迁移 / 归档（服务层能力）**：应用提供 `.aiproject`（标准 ZIP：manifest + 一致性数据库快照 + 声明附件）与开放目录两种跨机器载体，导入端会校验身份、路径、hash、资源限额并隔离 staging；导入后的项目只保留连接凭据引用（`env:`/`wincred:`），密钥正文与未声明文件不会跨机。**V1.0 候选的图形界面暂未暴露这两条入口**（见 [`known-issues.md`](known-issues.md)），当前通过应用服务层/测试驱动使用。

## 4. 恢复与回滚

### 4.1 崩溃恢复（日常）

- 翻译中断（程序被强制结束、机器崩溃、断电）后重启应用：
  - 超时租约被自动回收，中断的段回到可翻译状态，可重新排队翻译；
  - 已完成的段保留其结果与修订，不会被重复覆盖；
  - 模式/active Profile/文档选择/锁定等状态随数据库重新加载而恢复。
- 网络中断、模型超时、响应截断等失败会标记为可重试，重启或重试后重新翻译；永久失败保留可解释的错误与原始修订。

### 4.2 从迁移前备份回滚（版本回退）

若升级后发现问题需要退回升级前的数据：

1. 完全关闭应用。
2. 找到数据目录下最近的 `project.pre-upgrade-*.db.bak`。
3. 用该备份文件**替换** `project.sqlite`（可先把手头的 `project.sqlite` 另存一份）。
4. 重新启动应用。旧版数据与迁移历史恢复，应用会按需再次向前迁移。

回滚优先使用迁移前备份；不要手工删改迁移历史表。备份文件不会被应用自动删除，请自行决定保留策略。

### 4.3 数据完整性边界

- 导出、迁移、恢复的失败都不会污染数据库或既有目标文件（失败即停止，不产生半成品）。
- 应用不会静默删除外置的项目、备份或凭据；删除程序目录不会触碰用户数据。

## 5. 清理

- 完全卸载 = 删除程序目录 +（确认后）删除 `%USERPROFILE%\.transrealm`。
- 只想清空翻译数据但保留应用时，可在关闭应用后删除 `%USERPROFILE%\.transrealm\project.sqlite`（及旧备份），下次启动会重建空库。
- 删除前请确认备份与需要保留的项目已另行导出。

## 6. 凭据安全

- 应用只保存 `env:VAR` / `wincred:TARGET` 引用，密钥正文不进入数据库、日志、导出、归档或程序目录。
- 导入/跨机场景只会携带引用；目标机解析不到引用时给出可操作提示，不会把密钥随文件迁移。
